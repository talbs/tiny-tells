Tiny Tells{{wordmark}} Docs

Tiny Tells is one custom element, <tiny-tell>. It shows what your app is doing with a small animated character instead of a spinner. Pick one of six tells with the tell attribute and one of five states with state. Change the state and the tell springs into the new one.

Get Started

Three steps: load it, add a tell, change its state. Working with a coding assistant? Skip to Build with AI and let it do these for you.

1. Load It

Three ways to load it, all the same element. Pick the one that matches how you build. Flip on the play bundle and tells glance at the pointer, dance, and doze off.

Play Bundle npm CDN Self-Host

Using a bundler? Install the package and import it once, anywhere:

npm i tiny-tells
import 'tiny-tells';

The import registers the element as it runs. Types ship in the package. Need the class itself? Import it by name with import { TinyTell } from 'tiny-tells'.

No build step? Add the script tag:

<script type="module" src="https://cdn.jsdelivr.net/npm/tiny-tells@{{version}}/dist/tiny-tells.min.js"></script>
Keep the version in the URL until 1.0. A breaking change can’t reach your site until you choose to update.

Copy dist/tiny-tells.min.js from the package into your site and load it like any other module. Want to read or debug it? dist/tiny-tells.js is the same code, unminified. 

<script type="module" src="/js/tiny-tells.min.js"></script>

Put it next to the words it describes. label="" stops screen readers from saying the state twice. role="status" announces the words when they change. More on that.

Accessibility

A tell is a hint, never the message. The words carry the status. The tell is what you notice at a glance. Tiny Tells handles motion, contrast, forced colors, and flashing. The one thing it can’t know is what’s actually happening, so that part is yours.

Your Part

  1. Put words beside it. A tell is never the only signal.
  2. Hide its name when the words already say it with label="". It works like alt="" on a decorative image. Try it.
  3. If the status changes while someone’s on the page, put the words in a role="status" region so screen readers announce it. Keep the region in the page from the start, and hide what’s inside it, not the region. See how.
  4. If you change the colors, keep 3:1 against the surface (WCAG 1.4.11). Check yours.
  5. If it moves for more than five seconds, give people a pause button (WCAG 2.2.2). Copy one.
  6. If you load play, put noplay on busy lists, so only the tells you want playing do. See play.

Handled for You

  • A name. Shows up as an image named by its state, or by the label attribute.
  • Reduced motion. Holds one still pose per state, and play turns off.
  • Forced colors. Draws in the system text color in Windows High Contrast mode.
  • Contrast. Meets 3:1 with the built-in palette.
  • Flashing. Never more than three flashes a second (WCAG 2.3.1).
  • Off-screen. Stops animating while it’s scrolled out of view.
  • Pausing. Holds its current frame with the paused attribute.

Labels

Screen readers read a tell as an image named after its state, like “Working”. Set label to be more specific. Set label="" to hide the tell when the words beside it already say the state.

Use label, not aria-label. aria-label and aria-labelledby work too, and override label. Firefox ignores them before version 119, though, so label is the safe one.

Pausing

paused freezes a tell on its current frame. Remove it and the tell rejoins the shared beat.

Customize

Size

Usually you don’t set one.

Follow the Text

A tell sizes itself to the text it sits in: about 1.4 times the font size, never under 20px or over 48px. Under the hood that’s clamp(20px, 1.43em, 48px).

Pin a Size

Set --tell-size when a tell should hold one size whatever the text does (a toolbar, a table column). It inherits, so set it on the tell or any container above it:

Color

Five custom properties, one per state. Set them on :root or any container, with any CSS color, light-dark() included. Skip one and it keeps the built-in color. The play bundle adds a sixth for its dance.

The rule: 3:1 against the surface behind the tell. The built-in palette clears it in light and dark. Pick a palette below and the chips check it for you.

Use Your Design System’s Colors

Point the tokens at your system’s, and declare them on the same selectors your system uses to switch theme. The names below are stand-ins:

Set the tokens where the theme switches. A var() resolves where it’s declared. Set the tokens only on :root and a dark region still gets the light values.

Match the Text Color

color="current" drops the state colors and draws in the text color around the tell, even inside another component’s slot. Use it on a filled button or a badge, where green on brand blue looks like a mistake.

Match Light or Dark

Each tell has a light drawing and a dark one, and scheme picks. auto (the default) reads the color-scheme around it. Use invert for a tell on a filled badge or button.

Styling

Size and color cover most of it. Past that, you get two hooks. The drawing itself is one canvas, so there’s nothing inside to restyle.

  • The canvas: ::part(tell). Opacity, filters, transforms.
  • The state: :state(working), :state(done), and so on. Style the things around the tell by what it’s showing. These need newer browsers. The second line below is the fallback for older ones.

Matching working by attribute? Add tiny-tell:not([state]) too. A tell with no state is working.

Play Bundle

The same element and API, with three extras for the person at the screen. It costs under 2.5 KB more, gzipped. The core bundle reports status and that’s it. Reach for play when the tell is part of the product’s personality.

Extra Happens When
Glance a mouse pointer comes near
Dance someone taps it five times quickly, or you call tell.dance()
Doze an idle tell is left alone for 30 seconds. It wakes when the pointer comes back. Never on touch screens.
  • Skip it with noplay. The tell keeps its state animation, with no glance, tap dance, or doze. Use it where many tells sit together, like a dense table. tell.dance() still works.
  • Reduced motion and paused both switch play off.
  • Recolor the dance with --tell-color-dance (sky blue by default). Any CSS color works, light-dark() included. It wins over color="current", so a tell that matches its text can still dance in color.

Load it in place of the core bundle:

npm CDN Self-Host 
import 'tiny-tells/play';
 
<script type="module" src="https://cdn.jsdelivr.net/npm/tiny-tells@{{version}}/dist/tiny-tells-play.min.js"></script>
 
<script type="module" src="/js/tiny-tells-play.min.js"></script>
 From a CDN, load one bundle, not both. Each CDN file carries the whole element. Load both and the first one wins, with a console warning. From npm, importing both is safe since they share one element, but then every tell on the page plays.

Integrate

Frameworks and Editors

It’s a plain custom element. Anything that renders HTML renders a tell, and Svelte, Lit, and plain HTML need nothing else. React, Vue, and Angular each want one small setup step, below.

Types and Editors

  • TypeScript: dist/tiny-tells.d.ts types the element and exports TinyTell, TinyTellAttributes, TellName, TellState, TellColor, and TellScheme. The play bundle’s types add TellDanceEvent, TellAfterDanceEvent, and the dance events on addEventListener.
  • Custom Elements Manifest: dist/custom-elements.json describes the element to anything that reads the format: Storybook, docs generators, coding assistants. The package’s customElements field points to it, so most tools find it on their own.
  • VS Code: add the custom data file to html.customData for attribute autocomplete in HTML files. On the CDN or self-hosting, download the same file into your project and point the setting at it. 
{
  "html.customData": ["./node_modules/tiny-tells/dist/vscode.html-custom-data.json"]
}

React

React 19 works out of the box.

In React 18, leave paused off instead of setting it to false. React 18 writes every value as an attribute string, so paused={false} becomes paused="false", and that still pauses.

With TypeScript, drop this in any .d.ts file so <tiny-tell> type-checks in JSX. It works with React 18 and 19 types: 

import type { DetailedHTMLProps, HTMLAttributes } from 'react';
import type { TinyTell, TinyTellAttributes } from 'tiny-tells';

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      'tiny-tell': DetailedHTMLProps<HTMLAttributes<TinyTell>, TinyTell> & TinyTellAttributes;
    }
  }
}

Vue and Angular

Both need to be told <tiny-tell> isn’t one of their components. In Vue, pass this to the Vue plugin in vite.config.js: 

vue({
  template: { compilerOptions: { isCustomElement: tag => tag === 'tiny-tell' } },
})

In Angular, add CUSTOM_ELEMENTS_SCHEMA to the component that uses it:

@Component({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})

Agent Status

An agent run fits the five states. A spinner covers working. What it can’t show is warning: the run stopped and it’s waiting on a person. That’s the state that costs time when nobody notices it.

Map your SDK’s status to a state, set it on the tell, and put the words in a role="status" region. A chat reply counts as a run. A run someone stopped is your call (most apps go back to idle).

State The Run Is AI SDK LangGraph.js OpenAI Agents SDK Claude Agent SDK
working thinking or streaming status is submitted or streaming invoke() hasn’t returned run() hasn’t settled query() is still yielding
done finished status is ready after a reply returned with no __interrupt__ returned with no interruptions a result message with subtype success
error failed status is error invoke() threw run() threw any other result subtype, or it threw
warning waiting on a person a tool part in approval-requested __interrupt__ in the result result.interruptions has entries canUseTool hasn’t returned
idle not started status is ready before any reply nothing started yet nothing started yet nothing started yet

Set State and Words Together

The LangGraph, OpenAI, and Claude examples share this:

const tell = document.querySelector('tiny-tell');
const words = document.querySelector('[role="status"]');
const TEXT = { working: 'Thinking…', done: 'Done', error: 'Something broke', warning: 'Needs your OK', idle: 'Ready' };

const show = state => {
  tell.state = state;
  words.textContent = TEXT[state];
};
Call show() in the page, not next to the SDK. Those SDKs usually run on a server. Call it wherever the page hears about the run: a stream, a socket, or a poll.

AI SDK

  • ready means two things: nothing started yet, or a reply (or stop()) just finished. This example calls it done once there’s a reply on the page.
  • Approvals go back on their own with sendAutomaticallyWhen, so done means the tool really ran. 
import { useChat } from '@ai-sdk/react';
import { lastAssistantMessageIsCompleteWithApprovalResponses } from 'ai';

const TEXT = { working: 'Thinking…', done: 'Done', error: 'Something broke', warning: 'Needs your OK', idle: 'Ready' };

const stateOf = (status, messages) => {
  const parts = messages.at(-1)?.parts ?? [];
  if (parts.some(p => p.state === 'approval-requested' && !p.approval?.isAutomatic)) return 'warning';
  if (status === 'error') return 'error';
  if (status !== 'ready') return 'working';
  return messages.length ? 'done' : 'idle';
};

function RunStatus() {
  const { status, messages } = useChat({
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses,
  });
  const state = stateOf(status, messages);
  return (
    <p>
      <tiny-tell state={state} label="" /> <span role="status">{TEXT[state]}</span>
    </p>
  );
}
Skip automatic approvals. They pass through approval-requested too, with approval.isAutomatic set. Count them and the tell shows warning when nobody needs to act.

LangGraph.js

A paused graph comes back with __interrupt__ set. Answer it with new Command({ resume }) on the same thread and it’s working again: 

show('working');
try {
  const result = await graph.invoke(input, config);
  show(result.__interrupt__?.length ? 'warning' : 'done');
} catch {
  show('error');
}

OpenAI Agents SDK

A run that needs approval stops and fills result.interruptions. Approve or reject each one on result.state, then run again: 

import { run } from '@openai/agents';

show('working');
try {
  const result = await run(agent, input);
  show(result.interruptions.length ? 'warning' : 'done');
} catch {
  show('error');
}

Claude Agent SDK

The run doesn’t stop for approval. It waits inside canUseTool until you answer, so the tell switches to warning there and back when the person decides. askUser stands in for your own approval UI: 

import { query } from '@anthropic-ai/claude-agent-sdk';

const canUseTool = async (toolName, input) => {
  show('warning');
  const isAllowed = await askUser(toolName, input);
  show('working');
  return isAllowed ? { behavior: 'allow', updatedInput: input } : { behavior: 'deny', message: 'Declined' };
};

show('working');
try {
  for await (const message of query({ prompt, options: { canUseTool } })) {
    if (message.type === 'result') show(message.subtype === 'success' ? 'done' : 'error');
  }
} catch {
  show('error');
}

Testing Your App

  • Test DOMs (jsdom, happy-dom): tells go inert. Attributes and properties work, nothing draws, and nothing logs, so Jest and Vitest output stays clean.
  • Screenshot tests (Playwright, Puppeteer): emulate reduced motion. Every state holds one fixed pose, so screenshots match from run to run. 
await page.emulateMedia({ reducedMotion: 'reduce' });

Before It Loads

Until the script runs, <tiny-tell> is an empty inline element. Then the tell appears and shoves the words beside it over. A late tell is fine (the words already say the status). The layout shift isn’t, and it counts against your Cumulative Layout Shift.

Hold Its Space

Load reserve.css before the script. It gives every tell the box it’ll have once it loads, so nothing moves:

Events

The core fires no events. It only shows the state you set, so there’s nothing new to report. The play bundle fires two around a dance (dozing fires none, since the state stays idle). Both bubble and cross shadow roots, so listen on the tell or anywhere above it.

{{event-rows}}

  • Length: a dance lasts two loops, about 6.4 seconds.
  • No tell-dance while a tell is paused, under reduced motion, or mid-dance.

How It Works

A tell is animated like a character, not swapped like an icon. All six follow the same few rules, and the demos below are running them live.

One Beat, One Clock

Everything runs on a 0.8s beat. A loop is four beats (idle takes six). Every tell on the page shares one clock, so a row of them stays in time, and each lands its biggest move on the beat.

Handoffs

Change the state and the tell doesn’t cut to the new loop. It springs from wherever it is, keeping its momentum, so even a switch halfway through a move looks intended. A sprite sheet or a GIF would have to cut.

Small on Purpose

Tells drop detail as they shrink, so each still reads at 20px. At 32px and under, Eyes loses its glow and Dekatron’s ten cathodes merge into one ring.

Drawing

Each tell is one canvas at your screen’s full resolution, and off-screen tells stop drawing. On a recent laptop, 100 on screen run above 60 fps. On a CPU four times slower, they run at about 40. Try yours:

Tested

Every change is tested in Chromium, Firefox, and WebKit, and every tell has to pass the same checks:

  • stay inside its live area
  • loop without a seam
  • never flash more than three times a second
  • draw in system colors under forced colors

Contributing

Bugs go in an issue: the browser, the tell, the state, what you saw. A screen recording helps a lot. For anything bigger, open an issue before the pull request so we agree on it first.
